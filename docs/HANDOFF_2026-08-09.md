## Work order

### 1. Reproduce before extending

- Confirm the snapshot exists, the intended executable is selected, startup
  prints the expected policies, and one COW-on run reaches the exact golden
  boundary. The fixed route is expected to stop at the block budget while the
  guest is still live; success means the expected budget-stop followed by
  normal teardown and complete summary logs. Test debug-port `quit` and active-
  audio shutdown separately during lifecycle acceptance.
- Capture framework/title commits, executable hash, environment, host load,
  and raw log paths.
- If the source or executable differs, rebuild and rerun the existing 14-test
  suites before collecting timing.

### 2. Measure the current bottleneck

Produce one post-COW attribution table containing:

- submit reason counts and exclusive submit/fence/wait/materialization time;
- texture/TLUT versions, arena high-water, rollovers, and drains;
- fallback reason plus draw/triangle/pixel weight;
- CPU, DSP, and GX active/exclusive time;
- guest-audio samples, host-ring full wait, underruns, and drops;
- VI fields/XFB publications, distinct host presents, coalesced/dropped frames,
  and presenter wait/latency -- or explicitly state which values are
  unavailable.

Instrumentation must be opt-in, behavior-neutral, and cheap when disabled.
Discard instrumented wall time if the probe materially perturbs the route.

### 3. Repeat capacity fairly

When the host is quiet, use the same binary for interleaved COW-off/on runs.
Aim for at least three ABBA rounds if thermally admissible. Report every raw
wall, `683 / wall`, and milliseconds/event. Label this **unthrottled capacity**,
never displayed FPS.

### 4. Collect audio and presentation evidence separately

- First run the unthrottled audio-transport configuration. Producer wait is
  expected here; report `wait_ms / wall_ms` and do not treat it as presentation
  pacing.
- Separately run the paced headed configuration long enough to pass startup and
  exercise sustained playback. Without a pre-approved producer-wait/latency
  budget, report the measured ratio and leave latency acceptance open.
- Capture screenshots through the TCP debug surface before making any visual
  claim; inspect the images.
- Capture an in-run TCP `audio_state` proving a Windows endpoint is open before
  shutdown clears that flag. Require nonzero submitted/audible frames beyond
  the 8,192-frame startup cushion, `underruns == 0`, `dropped_frames == 0`,
  continued guest progress/input response, then separately require clean
  shutdown and complete final logs. If no endpoint opens, audio is **not run**,
  never passed.
- Record VI/presenter cadence independently of DrawDone. If it is unavailable,
  the mandatory result is **unknown/no presentation claim**.
- A deterministic PCM segment with frame count, sample rate, channel metadata,
  and hash plus an approved Dolphin/reference comparison is mandatory before
  any PCM-fidelity or audio-quality promotion. If capture/comparison is not
  available tonight, explicitly leave fidelity unvalidated.

### 5. Exercise the faithful floors

- Run the fixed suffix with `GCN_GX_BACKEND=software` and require the expected
  XFB boundary/hash and clean budget-stop teardown.
- Keep `GCN_DSP_THREAD` unset and capture evidence that synchronous DSP-LLE and
  AID remain active in both audio-off and audio-on configurations.
- No master force-interpreter route is currently documented. Do not claim an
  exercised CPU force-floor gate until a supported control is identified or
  added and validated; ordinary interpreter fallback evidence is not the same
  gate.

### 6. Decide; do not guess

- Texture/epoch pressure dominant: investigate lifetime, overlap, or arena
  drains before expanding TEV.
- Unsupported fallback dominant: refresh its weighted census before proposing
  batching or another exact TEV phase.
- CPU or DSP dominant: profile the current build before proposing AOT/HLE.
- Capacity above 66 but presentation below 60: investigate guest cadence and
  VI/presenter behavior; do not call it a failed capacity optimization.

Any optimized or HLE path must remain opt-in until parity-proven, retain loud
fallback, and keep software/interpreter/DSP-LLE modes forceable.
